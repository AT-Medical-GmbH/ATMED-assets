# Security Policy

## Overview

AT Medical GmbH takes the security and integrity of all assets hosted in this repository seriously. Although this repository contains static branding assets rather than executable code, we maintain strict governance to prevent the distribution of tampered, counterfeit or malicious assets under the AT Medical brand.

---

## Reporting a Security or Integrity Concern

If you discover a security issue, suspected asset tampering, unauthorised access or any other concern affecting the integrity of assets in this repository, please do **not** open a public GitHub issue.

Instead, report your concern confidentially to the AT Medical security team:

**Email:** [security@at-medical.com](mailto:security@at-medical.com)

Please include:

- A clear description of the issue or concern
- The specific asset(s) or path(s) involved
- Steps to reproduce or evidence of the issue
- Your contact details (optional but appreciated)

We aim to acknowledge all security reports within **48 hours** and to provide an initial assessment within **7 business days**.

---

## Scope

This security policy applies to:

- All assets hosted in this repository (logos, icons, wordmarks, branding elements, favicons, illustrations, templates, badges, diagrams)
- The repository configuration, metadata and CI/CD workflow definitions
- Any CDN or R2 deployment serving assets from this repository

---

## Asset Integrity

All assets in this repository are governed by automated integrity checks executed on every push and pull request. Any change to an existing asset in `assets/logos/` or `assets/wordmarks/` triggers a mandatory review by the AT Medical infrastructure team and design team before merging.

---

## Supported Versions

This repository does not ship versioned software. Asset updates are tracked in the `CHANGELOG.md`. At any point in time, the `main` branch represents the current authoritative state of all AT Medical brand assets.

---

## Responsible Disclosure

AT Medical GmbH follows responsible disclosure principles. Reporters who act in good faith and contact us privately will receive acknowledgement and be kept informed of resolution progress. We do not pursue legal action against good-faith security reporters.
